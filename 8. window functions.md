# PySpark Window Functions — Complete Guide (GitHub Ready)

---

## 📌 Overview

Window functions in **PySpark** allow you to perform calculations across a set of rows that are related to the current row without collapsing the dataset like `groupBy`.

Unlike aggregations, window functions **retain all rows**.

---

## 🧠 Key Concepts

| Concept   | Description                         |
| --------- | ----------------------------------- |
| Window    | Logical partition of data           |
| Partition | Groups rows (like GROUP BY)         |
| Order     | Defines ranking or cumulative logic |
| Frame     | Subset of rows within partition     |

---

## ⚙️ Setup

```python
from pyspark.sql import SparkSession
from pyspark.sql.window import Window
from pyspark.sql.functions import col, row_number, rank, dense_rank, sum

spark = SparkSession.builder.appName("WindowFunctions").getOrCreate()
```

```python
data = [
    (1, "HR", 5000),

]

columns = ["emp_id", "department", "salary"]

df = spark.createDataFrame(data, columns)
df.show()
```

---

## 🪟 Define Window Specification

```python
window_spec = Window.partitionBy("department").orderBy(col("salary").desc())
```

---

# 🔢 1. row_number()

## 📌 Definition

Assigns a **unique sequential number** to each row within a partition.

---

## 💻 Code

```python
df_row = df.withColumn("row_number", row_number().over(window_spec))
df_row.show()
```

---

## 📊 Output

| emp_id | department | salary | row_number |
| ------ | ---------- | ------ | ---------- |
| 1      | HR         | 5000   | 1          |
| 2      | HR         | 4000   | 2          |
| 3      | HR         | 4000   | 3          |
| 4      | IT         | 6000   | 1          |
| 5      | IT         | 5000   | 2          |
| 6      | IT         | 5000   | 3          |

---

## ✅ Key Points

* Always unique
* No ties handled
* Strict ordering

---

# 🏆 2. rank()

## 📌 Definition

Assigns rank with **gaps when there are ties**.

---

## 💻 Code

```python
df_rank = df.withColumn("rank", rank().over(window_spec))
df_rank.show()
```

---

## 📊 Output

| emp_id | department | salary | rank |
| ------ | ---------- | ------ | ---- |
| 1      | HR         | 5000   | 1    |
| 2      | HR         | 4000   | 2    |
| 3      | HR         | 4000   | 2    |
| 4      | IT         | 6000   | 1    |
| 5      | IT         | 5000   | 2    |
| 6      | IT         | 5000   | 2    |

---

## ⚠️ Important

* Duplicate values get same rank
* Next rank is skipped

---

# 🥇 3. dense_rank()

## 📌 Definition

Assigns rank **without gaps**, even when duplicates exist.

---

## 💻 Code

```python
df_dense = df.withColumn("dense_rank", dense_rank().over(window_spec))
df_dense.show()
```

---

## 📊 Output

| emp_id | department | salary | dense_rank |
| ------ | ---------- | ------ | ---------- |
| 1      | HR         | 5000   | 1          |
| 2      | HR         | 4000   | 2          |
| 3      | HR         | 4000   | 2          |
| 4      | IT         | 6000   | 1          |
| 5      | IT         | 5000   | 2          |
| 6      | IT         | 5000   | 2          |

---

## ✅ Key Difference from rank()

* No rank skipping

---

# 📈 4. Cumulative Sum

## 📌 Definition

Computes **running total** within a partition.

---

## 💻 Code

```python
window_cum = Window.partitionBy("department").orderBy("salary")

df_cum = df.withColumn("cumulative_salary", sum("salary").over(window_cum))
df_cum.show()
```

---

## 📊 Output

| emp_id | department | salary | cumulative_salary |
| ------ | ---------- | ------ | ----------------- |
| 2      | HR         | 4000   | 4000              |
| 3      | HR         | 4000   | 8000              |
| 1      | HR         | 5000   | 13000             |
| 5      | IT         | 5000   | 5000              |
| 6      | IT         | 5000   | 10000             |
| 4      | IT         | 6000   | 16000             |

---

## ⚠️ Note

* Ordering matters for cumulative calculations

---

# 🔍 Comparison Table

| Function   | Handles Ties | Gaps  | Unique Values |
| ---------- | ------------ | ----- | ------------- |
| row_number | ❌ No         | ❌ No  | ✅ Yes         |
| rank       | ✅ Yes        | ✅ Yes | ❌ No          |
| dense_rank | ✅ Yes        | ❌ No  | ❌ No          |

---

# 🎯 When to Use What

| Use Case                        | Function       |
| ------------------------------- | -------------- |
| Unique ranking                  | row_number     |
| Competition ranking (with gaps) | rank           |
| Compact ranking (no gaps)       | dense_rank     |
| Running totals                  | cumulative sum |

# 🚀 Complete Example

```python
from pyspark.sql import SparkSession
from pyspark.sql.window import Window
from pyspark.sql.functions import *

spark = SparkSession.builder.appName("FullExample").getOrCreate()

# Data
data = [
    (1, "HR", 5000),
    (2, "HR", 4000),
    (3, "HR", 4000),
    (4, "IT", 6000),
    (5, "IT", 5000),
    (6, "IT", 5000)
]

cols = ["emp_id", "department", "salary"]

df = spark.createDataFrame(data, cols)

# Window
w = Window.partitionBy("department").orderBy(col("salary").desc())

# Apply functions
result = df \
    .withColumn("row_number", row_number().over(w)) \
    .withColumn("rank", rank().over(w)) \
    .withColumn("dense_rank", dense_rank().over(w))

# Cumulative Sum Window
w2 = Window.partitionBy("department").orderBy("salary")

result = result.withColumn("cumulative_salary", sum("salary").over(w2))

result.show()
```

# 📌 Summary

* Window functions work on partitions without collapsing rows
* `row_number()` → unique sequence
* `rank()` → gaps in ranking
* `dense_rank()` → no gaps
* `sum().over()` → cumulative calculation

---

# ⭐ Best Practices

* Always define correct partition
* Always define ordering for ranking
* Use frame (`rowsBetween`) for advanced control
