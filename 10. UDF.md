# PySpark UDFs (User Defined Functions)

---

## 📌 Overview

**UDF (User Defined Function)** in PySpark allows you to create custom functions using Python and apply them to DataFrame columns.

Used when:

* Built-in functions are not sufficient
* Complex transformations are required

---

## ⚠️ Important Note

UDFs are **slower** than built-in PySpark functions because:

* They run in Python (not JVM optimized)
* Serialization & deserialization overhead

👉 Always prefer built-in functions if available.

---

## 🧠 Types of UDFs

| Type                      | Description                        |
| ------------------------- | ---------------------------------- |
| Scalar UDF                | Processes one row at a time        |
| Pandas UDF (Vectorized)   | Processes data in batches (faster) |
| UDF with Multiple Columns | Accepts multiple inputs            |
| UDF with Struct Return    | Returns multiple values            |

---

## ⚙️ Setup

```python
from pyspark.sql import SparkSession
from pyspark.sql.functions import udf, col
from pyspark.sql.types import *

spark = SparkSession.builder.appName("UDF Example").getOrCreate()
```

---

# 🔹 1. Scalar UDF (Basic UDF)

## 📌 Definition

A function applied row-by-row.

---

## 🧾 Example Dataset

| id | name | age |
| -- | ---- | --- |
| 1  | John | 25  |
| 2  | Sam  | 30  |
| 3  | Anna | 22  |

---

## 🧮 Example: Age Category

### 🎯 Goal

Categorize age into:

* Young (<25)
* Adult (>=25)

---

## 🧑‍💻 Code

```python
from pyspark.sql.functions import udf
from pyspark.sql.types import StringType

# Step 1: Python function
def age_category(age):
    if age < 25:
        return "Young"
    else:
        return "Adult"

# Step 2: Convert to UDF
age_udf = udf(age_category, StringType())

# Step 3: Apply UDF
df = spark.createDataFrame([
    (1, "John", 25),
    (2, "Sam", 30),
    (3, "Anna", 22)
], ["id", "name", "age"])

result = df.withColumn("category", age_udf(col("age")))
result.show()
```

---

## 📤 Output

| id | name | age | category |
| -- | ---- | --- | -------- |
| 1  | John | 25  | Adult    |
| 2  | Sam  | 30  | Adult    |
| 3  | Anna | 22  | Young    |

---

# 🔹 2. UDF Using Decorator

## 📌 Cleaner Syntax

```python
from pyspark.sql.functions import udf
from pyspark.sql.types import StringType

@udf(returnType=StringType())
def age_category(age):
    return "Young" if age < 25 else "Adult"

result = df.withColumn("category", age_category(col("age")))
```

# 🔹 3. UDF with Multiple Columns

## 📌 Example: Full Name

### 🧾 Dataset

| first_name | last_name |
| ---------- | --------- |
| John       | Doe       |
| Sam        | Smith     |

---

## 🧑‍💻 Code

```python
from pyspark.sql.types import StringType

# Python function
def full_name(first, last):
    return first + " " + last

# UDF
full_name_udf = udf(full_name, StringType())

# Data
df = spark.createDataFrame([
    ("John", "Doe"),
    ("Sam", "Smith")
], ["first_name", "last_name"])

# Apply
result = df.withColumn("full_name", full_name_udf(col("first_name"), col("last_name")))
result.show()
```

---

## 📤 Output

| first_name | last_name | full_name |
| ---------- | --------- | --------- |
| John       | Doe       | John Doe  |
| Sam        | Smith     | Sam Smith |

---

# 🔹 4. UDF Returning Multiple Columns (Struct)

## 📌 Example: Split Name

---

## 🧑‍💻 Code

```python
from pyspark.sql.types import StructType, StructField, StringType

# Schema for output
schema = StructType([
    StructField("first", StringType(), True),
    StructField("last", StringType(), True)
])

# Function
def split_name(name):
    parts = name.split(" ")
    return (parts[0], parts[1])

# UDF
split_udf = udf(split_name, schema)

# Data
df = spark.createDataFrame([
    ("John Doe",),
    ("Sam Smith",)
], ["name"])

# Apply
result = df.withColumn("name_struct", split_udf(col("name")))

# Extract fields
final_df = result.select(
    col("name"),
    col("name_struct.first"),
    col("name_struct.last")
)

final_df.show()
```

---

## 📤 Output

| name      | first | last  |
| --------- | ----- | ----- |
| John Doe  | John  | Doe   |
| Sam Smith | Sam   | Smith |

# 🔹 5. Pandas UDF (Vectorized UDF)

## 📌 Why Use?

* Faster than normal UDF
* Uses Apache Arrow
* Processes data in batches

---

## ⚙️ Setup

```python
from pyspark.sql.functions import pandas_udf
import pandas as pd
```

---

## 🧮 Example: Double Salary

### 🧾 Dataset

| id | salary |
| -- | ------ |
| 1  | 1000   |
| 2  | 2000   |

---

## 🧑‍💻 Code

```python
from pyspark.sql.types import IntegerType

@pandas_udf(IntegerType())
def double_salary(salary: pd.Series) -> pd.Series:
    return salary * 2

# Data
df = spark.createDataFrame([
    (1, 1000),
    (2, 2000)
], ["id", "salary"])

# Apply
result = df.withColumn("double_salary", double_salary(col("salary")))
result.show()
```

---

## 📤 Output

| id | salary | double_salary |
| -- | ------ | ------------- |
| 1  | 1000   | 2000          |
| 2  | 2000   | 4000          |

# 🔹 6. Registering UDF for SQL

## 📌 Use UDF in SQL Queries

---

## 🧑‍💻 Code

```python
spark.udf.register("age_category_sql", age_category, StringType())

df.createOrReplaceTempView("people")

spark.sql("""
SELECT name, age, age_category_sql(age) as category
FROM people
""").show()
```

# 🔹 7. When NOT to Use UDF

## ❌ Avoid UDF if:

* Built-in functions exist
* Performance is critical

---

## ✅ Better Alternatives

```python
from pyspark.sql.functions import when

result = df.withColumn(
    "category",
    when(col("age") < 25, "Young").otherwise("Adult")
)
```

---

# 🚀 Performance Comparison

| Approach           | Speed      | Recommendation      |
| ------------------ | ---------- | ------------------- |
| Built-in Functions | 🚀 Fastest | ✅ Best              |
| Pandas UDF         | ⚡ Fast     | 👍 Good             |
| Python UDF         | 🐢 Slow    | ❌ Avoid if possible |

---

# 🧪 Key Points Summary

* UDF = Custom logic in PySpark
* Scalar UDF = Row-wise execution
* Pandas UDF = Batch processing (faster)
* Always define return type
* Prefer built-in functions over UDF

---

# 📚 Best Practices

* Use Pandas UDF instead of Python UDF when possible
* Avoid heavy logic inside UDF
* Minimize data movement between Python and JVM
* Test UDFs on small data before scaling

---

# 🏁 Conclusion

UDFs are powerful but should be used carefully due to performance overhead.

👉 Use them only when necessary and prefer optimized Spark functions whenever possible.
